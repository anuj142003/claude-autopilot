# claude-autopilot v2 — Redesign

## Problem

v1 of claude-autopilot claims to route between BMAD and ECC, but the integration is superficial:

- **BMAD**: The CLAUDE.md describes BMAD persona behaviors in prose (e.g., "act as Mary, use Socratic questioning") instead of invoking actual BMAD slash commands that are installed at `~/.bmad/`. The 60+ real workflows with step files, templates, and validation are never used.
- **ECC**: Passive layers work (hooks auto-format, rules load into context), but the active layer — model-optimized agents like `code-reviewer` (Sonnet), `tdd-guide` (Sonnet), `planner` (Opus) — are never explicitly dispatched. The CLAUDE.md tells Claude to "self-review" instead of delegating to the `code-reviewer` agent.
- **Cost**: The main session runs everything on whatever model the user chose (typically Opus), even for implementation tasks that Sonnet handles equally well.

## Design Principles

1. **Route to real commands, not behavioral descriptions** — invoke actual BMAD workflows and ECC agents
2. **Discover at runtime, don't hardcode** — both frameworks evolve independently; the orchestrator must find what's available dynamically
3. **Delegate to reduce cost** — during BUILDING phases, dispatch to model-optimized ECC agents instead of doing everything in the main session
4. **Don't modify either framework** — BMAD workflows stay interactive in the main session; ECC agents keep their model assignments

## Architecture

Three layers:

### Layer 1: Phase Detection (unchanged)

The existing `detect-project-state.sh` hook runs at session start. It scans `_bmad-output/` and source directories to determine the lifecycle phase (IDEATION, PLANNING, SOLUTIONING, STORY_CREATION, READY_TO_BUILD, BUILDING, BROWNFIELD).

No changes needed — this works well.

### Layer 2: Discovery Protocol (NEW — replaces hardcoded registry)

Instead of maintaining a static mapping of commands, the CLAUDE.md teaches Claude *how to discover* available commands at runtime:

**BMAD discovery:**
- Glob `~/.bmad/cache/external-modules/**/bmad-skill-manifest.yaml`
- Read manifests to find commands matching the current need (by description, category)
- Invoke via `/<skill-id>`

**ECC agent discovery:**
- Glob `~/.claude/agents/*.md`
- Read frontmatter for name, description, model assignment
- Dispatch via the Agent tool with appropriate `subagent_type`

**ECC skill discovery:**
- Available skills are already listed in Claude's context
- Invoke via the Skill tool

Discovery happens on-demand — Claude searches only when it needs a specific type of tool, not upfront for all 60+ commands.

The SessionStart hook output is extended to include discovery paths:
```
BMAD_COMMANDS_PATH: ~/.bmad/cache/external-modules/**/bmad-skill-manifest.yaml
ECC_AGENTS_PATH: ~/.claude/agents/*.md
ECC_SKILLS: (already in context)
```

### Layer 3: Decision Framework (REWRITE of CLAUDE.md)

The CLAUDE.md contains no behavioral descriptions or persona instructions. Instead, it has:

**Part 1 — Discovery instructions**: How to find BMAD workflows, ECC agents, and ECC skills (the search patterns above).

**Part 2 — Routing rules**: When to search which framework, based on phase and user intent:

- **PLANNING phases** (IDEATION through STORY_CREATION): Search BMAD workflows first. Fall back to ECC planner/architect agents if no BMAD match.
- **BUILDING phases** (READY_TO_BUILD, BUILDING): Delegate to ECC agents. Search BMAD TEA module for test architecture needs.
- **REVIEW**: Use both — BMAD for acceptance criteria validation, ECC code-reviewer for code quality.

**Part 3 — Delegation instructions**: During BUILDING phases, minimize work in the main session. Delegate to ECC agents (they have optimized model assignments). The main session should:
1. Read story/requirements
2. Decide which agent(s) to dispatch
3. Review agent output
4. Report to user

## Cost Optimization

Cost savings come from the BUILDING phase (where most tokens are spent) through agent delegation:

| Task | Runs as | Model | Pricing tier |
|------|---------|-------|-------------|
| BMAD planning workflows | Main session | User's choice | User controls |
| Implementation planning | ECC planner agent | Opus | Premium (but scoped) |
| Writing tests | ECC tdd-guide agent | Sonnet | Standard |
| Code implementation | Delegated agent | Sonnet | Standard |
| Code review | ECC code-reviewer agent | Sonnet | Standard |
| Security scanning | ECC security-reviewer agent | Sonnet | Standard |
| Documentation | ECC doc-updater agent | Haiku | Economy |

The main session (Opus) becomes a thin orchestrator during BUILDING, delegating bulk work to cheaper models.

## What Changes

| Component | v1 | v2 |
|-----------|-----|-----|
| `detect-project-state.sh` | Detects phase | Detects phase + outputs discovery paths |
| `CLAUDE.md` | Behavioral descriptions ("act as Mary") | Discovery protocol + routing rules + delegation instructions |
| `unified-orchestration.md` | Artifact naming conventions | Same + routing rule reference |
| BMAD integration | Prose descriptions of personas | Runtime discovery of actual BMAD slash commands |
| ECC integration | "ECC hooks are active" | Explicit agent dispatching with model-aware delegation |
| Cost optimization | None | Automatic via agent model assignments |

## What Stays the Same

- Phase detection logic and artifact conventions
- BMAD workflows run interactively in the main session (not dispatched to sub-agents)
- ECC hooks and rules continue working passively
- Install script structure (though content updates needed)
- `_bmad-output/` directory conventions

## Risks

1. **Discovery overhead**: Claude scanning manifest files adds tool calls. Mitigated by on-demand scanning (not upfront) and caching mental model within a session.
2. **BMAD manifest format changes**: If BMAD changes its manifest schema, discovery breaks. Mitigated by the manifests being a stable API in BMAD's architecture.
3. **Agent delegation quality**: Sub-agents have less context than the main session. Mitigated by passing story/requirements context when dispatching.
4. **User confusion**: Users who expect Claude to "be" Mary or Winston may find the tool-routing approach less personal. Mitigated by BMAD workflows themselves providing the persona experience when invoked.
